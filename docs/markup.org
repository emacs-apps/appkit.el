#+title: Appkit markup
#+options: toc:2 num:nil

Appkit markup is a protocol-neutral semantic document with native rendering
and source codecs.  Clients use it to show formatted provider messages and to
parse what users type before encoding it for their provider.

A markup document is a transient value, not a draft, a canonical provider
message or a transport snapshot.  The provider object stays canonical.  A client
may cache documents only in an App-owned bounded cache whose keys are
revision-qualified and contain no secrets.

Appkit owns document values, normalization, native insertion, codecs,
structured-object fencing, codec selection, preview and plain-text export.
Clients own provider adapters and provider-exact codecs, wire encoders,
identity and URL policy, actions and spoiler state, and transport.

* Entry paths

#+begin_example
structured provider value -> client adapter -> document
markup source text        -> codec          -> document
#+end_example

Structured provider data, such as Slack ~rich_text~ or Zulip's rendered HTML,
is adapted directly into a document.  It is never printed to markup and parsed
again.  Provider markup strings, such as Discord content, go through a codec the
client registers.  A client must choose a codec explicitly before ordinary
protocol text is interpreted as markup.

* Document model

Documents are a closed family of structs with public constructors and no
mutators.  Never ~setf~ a captured document.

| Blocks       | Content                                                  |
|--------------+----------------------------------------------------------|
| paragraph    | inlines                                                  |
| heading      | level 1–6, inlines                                       |
| quote        | blocks                                                   |
| list         | ~ordered~ / ~unordered~, optional positive start, items  |
| list item    | blocks, including nested lists                           |
| preformatted | exact text, optional opaque language name                |
| object block | opaque client value, fallback blocks                     |

| Inlines    | Content                                                  |
|------------+----------------------------------------------------------|
| text       | exact text and styles                                    |
| link       | URL and styled text label runs                           |
| object     | opaque client value, fallback inlines, styles            |
| line break | an explicit break within the block                       |

Styles are ~bold~, ~italic~, ~underline~, ~strike~ and ~code~.  A link label holds
only text runs: no nested link, object or line break.  Inline code and
preformatted text are literal; nothing inside them is parsed.

Provider-only structures are object nodes rather than new node types: mentions
with exact IDs, spoilers, custom emoji, timestamps, unsupported blocks.  Generic
rendering, printing and export traverse only their fallback children.  Only the
owning client inspects an opaque value, and errors never print one.

** Normalization

Constructors and ~appkit-markup-normalize~ establish these invariants:

- semantic strings carry no text properties, and text nodes contain no newlines;
- empty text, paragraphs, headings, quotes and lists are removed, while empty
  preformatted blocks, object fallbacks and list items are kept;
- adjacent text with equal styles is merged, and styles are canonical and
  duplicate-free;
- list nesting is expressed only by a list inside a list item;
- languages and URLs are opaque strings.  Appkit does not infer a language or
  certify a URL;
- opaque values compare only by identity or a client-supplied equality.

~appkit-markup-validate~ and ~appkit-markup-equal-p~ check and compare documents.
Errors and diagnostics never include text, URLs, languages, opaque values or
code.

* Native rendering

~appkit-markup-ui-insert-document~ inserts a document as native text, faces,
display prefixes and Appkit action spans, and returns its exact bounds.  It is
compatible with an ~appkit-discussion~ body inserter's ~(prefix properties)~.

- Insertion is non-interactive unless ~:interactive-p~ is non-nil.
  Non-interactive output, used for previews, never calls client callbacks:
  links are inert, objects show their fallback, and code is fixed-pitch.
- Interactive insertion calls the client's callbacks.  ~:link-action~ maps a
  URL to a zero-argument action or nil.  ~:object-inserter~ and
  ~:preformatted-inserter~ receive their node and may only insert forward.
  ~:quote-style~ maps a quote depth to a prefix and face.
- Outer ~:properties~ cover the whole region but may not contain
  renderer-owned face, display, prefix, keymap or action properties.
- Blocks are separated by a blank line; ~:block-spacing nil~ makes them
  compact.  Insertion is atomic: an error leaves nothing behind.

Quote and list geometry is display-only, so copying and export do not depend
on rendered prefixes.

~appkit-fontify-string~ supplies code faces from a client-selected mode.
Parsing never calls it.

* Codecs

#+begin_src emacs-lisp
(appkit-markup-register-codec 'example-markdown
  :label "Example" :parse #'example--parse :print #'example--print)

(appkit-markup-parse 'markdown source :context context :object-classifier classifier)
(appkit-markup-print 'org document :context context :object-printer printer)
#+end_src

Built-in codecs:

- ~plain~: literal text with no invented syntax;
- ~org~: real ~org-element~ parsing in a temporary buffer, without enabling Org
  mode, Babel, Font Lock or hooks;
- ~markdown~: CommonMark/GFM through the pinned GNU Emacs ~markdown~ and
  ~markdown-inline~ Tree-sitter grammars, without enabling ~markdown-ts-mode~.

The Markdown grammars are never installed during parsing.  Check
~appkit-markup-markdown-ts-ready-p~, and install them explicitly with
~appkit-markup-markdown-ts-install-grammars~ (the same commit GNU Emacs pins).

A parse result holds a validated document, bounded diagnostics (kind, severity,
source bounds) and side-channel objects.  Malformed user markup becomes literal
text, and parsing continues.  A print result holds property-preserving source
and semantic-loss records (kind and structural path).  Unsupported semantics
keep visible fallback; Markdown has no underline, for example, so printing an
underline reports a loss rather than silently restyling it.  Codecs guarantee
semantic round trips, not byte-for-byte ones.

The Org and Markdown parsers accept a client ~:context~ plist of node builders:
~:image~ ~(URL ALT)~, ~:table~ ~(ROWS)~, ~:anchor~ ~(ID)~ and, for Markdown,
~:link~ ~(URL CHILDREN)~.  Builders only construct nodes.  They must not fetch
images, follow links or touch application state.

* Structured objects

Before parsing, Appkit finds the composer's structured input objects (see
[[file:chat.org][chat]]).  The ~:object-classifier~ receives each payload and its
visible label, and returns:

- ~semantic~ (the default): the occurrence becomes an unforgeable placeholder
  the codec treats as one literal atom, restored as an inline object after
  parsing;
- ~(side-channel . KEY)~: the occurrence is removed from the source and returned
  under KEY, for example an attachment;
- ~(reject . KIND)~: parsing stops with a diagnostic instead of flattening or
  deleting the object.

A missing, duplicated, split or reordered placeholder invalidates the result.
Placeholders exist only during one parse call and never reach a document,
buffer, cache key or log.  When printing, the ~:object-printer~ returns exact
source for an object node, or nil to fall back to its visible children and
record a loss.

* Composing

~appkit-markup-compose-setup~ adds codec policy to a generic compose session
(see [[file:compose.org][compose]]):

#+begin_src emacs-lisp
(appkit-markup-compose-setup
 :codecs '(markdown org plain)
 :active-codec 'markdown
 :object-classifier #'example--classify
 :object-printer #'example--print-object)
#+end_src

- No prefix uses the active codec, one ~C-u~ the second configured codec, two
  the third.  An out-of-range prefix is a user error.  The client decides which
  commands accept the prefix.  Changing the persistent active codec advances
  the compose generation once.
- ~appkit-markup-compose-capture~ freezes the generation, chosen codec, context,
  object printer and the parsed document with its diagnostics and side
  channels.  Preview (~appkit-markup-compose-preview~) and provider output
  (~appkit-markup-compose-output~) consume that one capture and never reread the
  buffer.  Inspect semantic losses before transport.
- Show the active codec in compose status, so source is never parsed under an
  unknown grammar.
- To edit an existing formatted message, adapt it to a document, pick the
  first configured codec that prints it without loss, and make that codec
  active.  If none is lossless, show the losses before replacing the source.

One codec applies to the whole capture.

* Plain text and safety

~appkit-markup-plain-text~ exports visible text, links, lists, quotes, code and
object fallbacks without provider actions, for accessibility, summaries,
notifications and copying.  It is not a wire encoder: clients produce provider
fallback text themselves.

Markup operations are local and deterministic.  No codec does network, file,
subprocess or package work.  None evaluates code or runs user hooks, and none
mutates its input.  Source and object counts are bounded.  Appkit keeps no global
source or document cache.
