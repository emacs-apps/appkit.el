#+title: Appkit integrator guide
#+options: toc:2 num:nil

This guide is for authors of Appkit clients.  It is not an end-user manual.
Detailed accepted designs live in [[file:compose.org][compose surfaces]] and
[[file:markup.org][markup documents]].  Terms are defined at the surface that
owns them rather than in a separate glossary.

* Ownership

Appkit owns lifecycle, update mechanics, and reusable presentation.
Clients own application state, protocol adaptation, and branding.

/Client semantics/ means protocol-specific meaning, validation, capability,
persistence, transport, and error behavior.  Appkit owns reusable mechanisms;
it does not turn client semantics into global policy.

** Appkit

- Application sessions, buffer views, and owned timers, hooks, and
  processes
- Owner-scoped keyed FIFO task queues with bounded concurrency
- Stable-key read-only projections with presentation dependency
  indexing, coalesced invalidation, and semantic position preservation
- Generated-content, property-only, and editable transactions
- Stable-key EWOC reconciliation and independent semantic point and
  viewport
- Mode-neutral compose sessions, chat composers, discussion rows,
  directories, action spans, transfer controls, and name coloring
- HTTPS-only media acquisition, preview processes, and media-card
  actions
- Optional Evil bindings without a runtime Evil dependency

** Clients

- Protocol objects, validation, persistence, and error meaning
- Transport, including how progress is measured and how cancel aborts
  that transport
- Identity keys, faces, and self or system color overrides
- Cursor and page semantics, remote-frontier observations, and when a
  response reaches latest
- Logical media cache keys and wire-resource state

* Surfaces

** Action spans

An action span is one buffer region carrying a client-supplied zero-argument
action.  ~appkit-ui-add-action~ makes it activatable by ~RET~, graphical
~<return>~, or primary click.  Help text describes the action itself; Appkit
does not infer a protocol target or install a client keymap.
Hover defaults to ~highlight~; pass ~:mouse-face nil~ to disable it without
disabling activation.  A terminating newline retains its action and face but
is excluded from hover, so adjacent multi-line action blocks remain separate.

Native control maps own both Return events, so application and Evil bindings
cannot steal graphical Return before Emacs translates it to ~RET~.  Use
~appkit-ui-insert-action-button~ for ordinary text buttons and
~appkit-ui-make-action-row~ for rows; existing native button constructors can
use ~appkit-ui-button-map~.  Do not put control activation only in a major-mode
Evil map or modify Emacs's global ~button-map~.

** Compose primitives

The exact source-backed contract is documented in
[[file:compose.org][compose surfaces]].

~appkit-compose-setup~ attaches protocol-neutral editing primitives to the
current buffer without changing its major mode or document model.  The client
supplies an owned snapshot function and, when only part of the buffer is
semantic source, editable source bounds.

Appkit owns exactly two reusable mechanisms:

- a monotonic semantic generation and immutable
  ~appkit-compose-capture~ result;
- one view-local effect owner with stale-callback fencing, optional progress,
  and cancellation request handling.

Appkit does not save drafts, schedule autosave, decide close policy, persist an
outcome, or classify completion as accepted, rejected, unknown, cancelled, or
saved.  Those meanings belong to the client reducer.  Finishing an owner only
retires its view-local authority.

Generated chrome must use ~appkit-compose-without-tracking~.  Semantic changes
outside editable text, such as an attachment or identity selection, call
~appkit-compose-touch~ exactly once.  A client may compare the captured
generation with its own durable revision, but Appkit does not own that durable
frontier.

** Child compose editors

Use ~appkit-compose-edit-buffer~ when one client-owned string needs a temporary
native major-mode editor.  Pass the exact live App/Surface owner and a content-free
buffer name.  Appkit owns recursive finish/cancel interaction and buffer
lifecycle only; language selection, validation rules, structured-object
insertion, and wire encoding remain client responsibilities.

** Chat compose

~appkit-chat-compose-mode~ is the chat-specific multi-part editor.  Committed
items are generated timeline rows and the trailing chatbuf composer edits one
item at a time.  Use it for ordered social post threads, not as the universal
Compose model.

The client owns each item’s protocol metadata.  Appkit owns the single ordered
item sequence, row/input geometry, and structural revisions.  Load a complete
draft with ~appkit-chat-compose-set-items~ and read it with
~appkit-chat-compose-items~; do not mirror that sequence in another buffer-local
variable.  Status fields use the generic ~appkit-compose-*~ presentation
functions.

Pass the owning App to ~appkit-chat-compose-setup~ with ~:app~.  The editor uses
a Generated Surface without replacing a client mode derived from
~appkit-chat-compose-mode~.  Stopping that Surface preserves its buffer and
draft, but revokes runtime work; refreshing it does not create a replacement App.

~appkit-chat-compose-set-items~ installs a programmatic draft snapshot without
resetting its source generation or active compose operation.  Persisting uploaded
attachment IDs or a confirmed thread prefix therefore does not cancel publication.
Use ~appkit-compose-reset~ explicitly when discarding the compose session.

Part bodies remain plain strings in Appkit 0.3.0; the chat-compose item merge
removes text properties.  Use the property-preserving ~appkit-chatbuf~ input
state directly when structured objects must survive capture.

** Markup documents

[[file:markup.org][Markup documents]] define the semantic model, native UI,
codec registry, structured-object fencing, codec selection, preview, and
plain-text export contracts.

Appkit 0.3.0 ships ~appkit-markup~, ~appkit-markup-ui~,
~appkit-markup-codec~, ~appkit-markup-codecs~, and
~appkit-markup-compose~.  Direct provider adapters still construct Documents
without printing and reparsing provider data.

Source-backed compose setup layers on an existing generic compose session:

#+begin_src emacs-lisp
(appkit-compose-setup
 :snapshot-function #'client-property-preserving-source
 :source-bounds-function #'client-source-bounds)

(appkit-markup-compose-setup
 :codecs '(markdown org plain)
 :active-codec 'markdown
 :object-classifier #'client-classify-object
 :object-printer #'client-print-object)
#+end_src

~appkit-markup-compose-capture~ freezes generation, selected source codec,
context, object-printer identity, parsed Document, diagnostics, and side
channels.  Use that same capture for
~appkit-markup-compose-preview~ and ~appkit-markup-compose-output~.  Inspect
losses before transport; never silently flatten unsupported semantics.

~org~ uses built-in ~org-element~ without enabling Org mode or hooks.
~markdown~ directly uses the pinned GNU Emacs block and inline Tree-sitter
grammars without enabling ~markdown-ts-mode~ or installing grammars during
parse.  ~plain~ treats syntax markers literally.  Universal prefixes select
later configured codecs in the same order as Telega.  One active-codec change
calls ~appkit-compose-touch~.

For incoming presentation, construct a normalized Document and call
~appkit-markup-ui-insert-document~.  Use ~:interactive-p nil~ for previews;
Appkit then invokes no link/object/code callback and traverses stored fallback.

** Inline translation

~appkit-translate~ is optional; requests must come from explicit user actions.
Supply a stable account-scoped ~:key~, the exact displayed snapshot's ~:version~,
and app-exported plain ~:text~—never rendered buffer text or implicitly included
hidden content.  Optional ~:data~ carries platform input.

Use ~appkit-translate-request~ or ~appkit-translate-request-many~ with a live
App or Surface owner.  Render ~appkit-translate-insert~ below the unchanged
original; rendering needs only key/version and must not start requests.
Use ~appkit-translate-enable~ when source identities need mapping to projection
rows.  Owner disposal cancels queued work and revokes late callbacks.

~appkit-translate-target-language~ defaults to ~"zh"~.
~appkit-translate-backend-function~ defaults to the optional Respond backend,
which requires its own Codex authentication; platform adapters may override it.
There is no automatic retry or fallback.  Backend and queue contracts live in
the docstrings in ~appkit-translate.el~, not a second API specification here.

** Transfer control

A timeline transfer control presents one upload or download.  The
client supplies direction, state, optional 0-1 progress, optional
byte counts, and a cancel or download action.  Appkit draws the bar
and measure.  It does not own a file, HTTP request, or job model.

** Chat buffers

~appkit-chatbuf-mode~ is the writable base.  Clients register a
timeline-only minor mode with ~appkit-chatbuf-use-timeline-mode~.
Appkit clamps prompt motion, repairs structured input objects, and
keeps generated content read-only even when the composer is hidden.

Set ~appkit-chatbuf-input-sync-function~ to synchronize
protocol-specific draft state.  Do not install a second after-change
controller.

Rendering consumes canonical input; do not synchronize input back from generated
buffer text during rendering or recovery.  A chat timeline cache belongs to one
exact Surface incarnation, even when a replacement reuses the same buffer.

Canonical chatbuf input and ~appkit-chatbuf-input-string~ preserve text
properties.  Structured input objects carry opaque payload, unique occurrence
identity, original visible text, and boundary sentinels.  Atomic deletion and
repair operate on complete occurrences.  Shared input history currently skips
object-bearing entries.

Copying strips display-only properties from generated content before the input
boundary, while retaining editable structured-object properties even when one
selection spans both regions.  Clients should not replace this shared filter
with a whole-buffer property stripper.  Input deletion and replacement respect
~buffer-read-only~; failed replacement preserves the original input text.

Construct compact content with
~appkit-ui-one-line-preview-create~.  Its optional propertized prefix
is atomic, uses its underlying text as the terminal fallback, and
declares its graphical width with ~:prefix-columns~.  Appkit preserves
display properties, styles only the textual leading span, and bounds the
combined fragment through ~appkit-ui-render-one-line-preview~.

Pass the same preview model as ~:preview~ to
~appkit-presentation-one-line-row-create~ or ~appkit-chatbuf-aux-render~.  The
directory renderer places it in one row column; the chatbuf renderer
places it on the second line of the reply/edit card.  One-line rows accept
~:context-open~ and ~:context-close~ delimiters; Appkit measures their actual
display widths and owns their geometry while the client selects their
presentation meaning.  Clients retain protocol objects, media selection and
acquisition, labels, identity faces, and resource invalidation.

Use ~appkit-chat-avatar-one-line-string~ for identity icons in rows, prompts,
compact messages, and annotations.  It preserves the source aspect ratio,
sizes the image to one current text line with character-relative units, and
adds no visible padding.  Set row ~:icon-slot-width~ to ~auto~ to insert the
icon at its natural width without a reserved slot or separator; keep numeric
slots for deliberately aligned text glyphs.

Build compact media with ~appkit-media-one-line-preview-image-from-file~ and
display it with ~appkit-media-one-line-image-display-string~.  The default
thumbnail budget is two unscaled character columns by one text line; its
displayed width and height follow text zoom together.  Cached source geometry
does not depend on the zoom level at acquisition.

Use ~appkit-media-image-display-string~ for inline image occurrences.  Each
occurrence has its own full-image display slice while retaining the source
image resource, so adjacent identical images remain separate and Canvas pixels
and live updates remain intact.  Treat the ~display~ property as a display
specification, not necessarily a bare image descriptor.  Preparing strings is
inert; insertion boundaries mount independently owned video.el occurrences.

** Discussion

Derive read-only note, topic, and reply-tree modes from
~appkit-discussion-mode~.  It owns default native soft wrapping; clients must
not repeat ~visual-line-mode~, ~word-wrap~, or ~truncate-lines~ setup.
Editable timelines retain ~appkit-chatbuf-mode~ and its
~appkit-chatbuf-wrap-long-lines~ and ~appkit-chatbuf-use-visual-fill-column~
options.  Both base modes use ~appkit-ui-set-soft-wrap~, which preserves
rendered prefixes without enabling an automatic continuation-prefix producer.
Chat clients change wrapping through ~appkit-chatbuf-set-soft-wrap~ so the
buffer-local preference remains synchronized.

/Discussion depth/ is visual reply nesting under a parent.  A /discussion
connector/ continues or ends a linear ancestor chain without changing that
depth.  Discussion rows accept both plus optional pre-heading context.  Clients
supply the context text; Appkit does not interpret it as a Renote, reply, quote,
or protocol thread.

~appkit-discussion-connector-style~ selects ~fringe~ (the graphical default
with a terminal text fallback), ~text~, or ~none~.  Customize
~appkit-discussion-fringe-connector~ for foreground/background color and
~appkit-discussion-fringe-bar-width~ or
~appkit-discussion-fringe-bar-position~ for generated geometry.  Advanced
configurations may register a bitmap with ~define-fringe-bitmap~ and assign its
symbol to ~appkit-discussion-fringe-bitmap~.

** History

The shared history controller owns exact buffer-local window edges,
unknown, partial, loading, and authoritative-empty state, opaque
request ownership, strict slicing, automatic edge gates, and passive
delimiter geometry.

** Scroll edges

Use ~appkit-scroll-observer-install~ when a view pages application-owned
content near a visible buffer edge.  The observer unifies buffer-local
~post-command-hook~, ~window-scroll-functions~, and
~window-size-change-functions~ handling.  Measurements run after redisplay,
validate the owning view and every displayed window, and report visible start
and end positions clamped by optional boundary functions.  Edge callbacks own
thresholds, cursors, loading and exhaustion gates, requests, and retry policy.

~appkit-scroll-near-start-p~ and ~appkit-scroll-near-end-p~ implement the
shared character-distance convention; a nil threshold disables the check.
After committing a page and synchronizing its projection, call
~appkit-scroll-observer-check~ so a short page can request another eligible
page.  The request callback must close its loading gate synchronously before
starting asynchronous work.

Keep viewport observation independent of projection invalidation: a height-only
resize changes visible edges without requiring width-dependent rows to reflow.

** Stable-key selection

~appkit-selection~ provides protocol-neutral selection values.  Store the value
in the client Surface model and return replacements from transitions using
~appkit-selection-set~, ~appkit-selection-toggle~ (clear/restore), and
~appkit-selection-forget~.  Treat values and their key lists as immutable.
Projection caches never own persistent selection.

~appkit-chat-timeline-keys-in-range~ maps a half-open rendered range to distinct
row keys, excluding the composer.  A row leaving that range or disappearing
from a projection does not imply deletion.  Only the client's authoritative
deletion transition should forget a key, including its restorable mark.

Selection presentation belongs to ~appkit-chat-ins~, not individual clients.
After inserting a selected message, call
~appkit-chat-ins-apply-message-selection~ with its heading/body bounds,
excluding preceding date and unread dividers.  Apply it once to the fresh
rendering; normal row replacement removes the decoration when unmarked.
It composes the strip with existing avatar and content prefixes on both
logical and wrapped lines, without changing text or content faces.
Customize ~appkit-chat-selection-marker~ for the shared appearance.

Clients still own target ordering, selectability, action cardinality,
permissions and transport.  Capture exact Surface identity and stable keys for
menus; resolve current objects at execution without falling back to a new point
target.  Batch requests should advance through committed transitions and owned
Effects, not renderer callbacks.

** Media

Callers adapt backend objects into canonical resource descriptors and explicit
preview metadata.  Appkit owns HTTPS-only atomic acquisition for explicit
image and file transfers, byte-level image cache finalization, lifecycle-bound
video sessions and presentation surfaces, and protocol-restricted preview and
audio-player processes.

Normal renderers prepare source-backed images, not players.
~appkit-media-preview-image-from-file~ and
~appkit-media-one-line-preview-image-from-file~ retain the original local
resource with passive interaction.  ~appkit-media-animated-image-p~ reports
source capability independently of the autoplay preference.  Local GIF, APNG,
WebP, and Lottie capability is determined centrally from content, including
extensionless cache files.  There is no separate image.el animation lifecycle.
Frame-specific image capability queries do not select the frame or move point.

A media attachment view is one item's preview, label, description, transfer
state, and actions.  It is presentation, not the readable or displayable media
resource and not a client attachment model.

For row-sliced image montages, use
~appkit-media-cropped-preview-image-from-file~ to center-crop a local file into
an exact box.  Its optional ~(TOP RIGHT BOTTOM LEFT)~ transparent insets
reserve pixel gutters without changing the box or its line-slice geometry.

Use ~appkit-media-horizontal-strip-image~ when several files must remain one
unbreakable display object.  It preserves a shared height, reserves explicit
pixel gutters and missing-file geometry, and exposes each item as an image-map
hot spot.  Items may override their display width, request center-cover instead
of natural-ratio containment, and add the shared translucent circle-and-triangle
video marker with ~:play-icon~.  The optional pixel offset moves the SVG
~viewBox~ while keeping display width fixed; hot spots are clipped and
translated into visible coordinates.

Treat the returned descriptor as immutable.  Unchanged scenes reuse descriptors
within the current buffer while live media tracks retain them; weak cache values
do not extend those tracks' lifetimes.  File replacement, scene geometry, and
presentation settings invalidate reuse.  Construction does not decode the SVG:
display code chooses the final slice height before rasterization is needed.

Use ~appkit-media-video-session-create~ when an application may present one
video in more than one place.  The Appkit wrapper owns the canonical resource,
stable cache identity, cache policy, and cache-completion update; its embedded
video.el ~video-session~ owns the single player and presentation leases.
~:request-headers~ configures playback transport without entering canonical
resource or cache identity.  ~:live t~ forces live, non-seekable behavior when
protocol discovery is ambiguous.  Sessions are intentionally not globally
deduplicated by cache key: separate user activations have independent playback
state.

Create an in-buffer surface with ~appkit-media-video-inline-create~.  Promote
that exact surface with ~appkit-media-present-video-inline~, or present its
Appkit session with ~appkit-media-present-video-session~.  Both paths retain
one video.el session, so playback position, desired play/pause state, canonical
mute, rate, buffering ranges, and sparse network cache remain continuous.
Closing either surface does not interrupt the other; video.el closes the player
after its last inline or dedicated lease disappears.  A client's optional
~:close-function~ runs exactly once after video.el retires the inline surface.

Expert inline hosts can pass ~:controls-p nil~ to omit video.el's transport
hot spots and retain their own pointer policy.  Standard media occurrences
derive this from their interaction policy; passive images, open-only images,
and still-image viewer links do not acquire a play/pause hot spot.

Use ~appkit-media-image-with-resource~ when a poster represents a different
original resource, needs media controls, or must resolve an original on demand.
It returns an immutable poster copy and replaces any previous playback plan;
it does not acquire resources, register owners, or start playback.  RESOURCE
is a canonical resource alist or nil.  ~:kind~ is ~image~ or ~video~.
Interaction is explicit:

- ~:interaction nil~ preserves enclosing links, navigation, and reaction
  buttons.  This is the default of source-file preview factories.
- ~:interaction 'media~ supplies RET/click to play/pause animated images and
  videos, or open a still image in the viewer.  This is the default of
  ~appkit-media-image-with-resource~.
- ~:interaction 'open~ always opens the viewer.

~:autoplay~ permits visible animated images to start after insertion when
~appkit-media-inline-animation-enabled~ and Canvas are available.  It never
autoplays videos or reveals transport controls.  Static passive posters need
no runtime host.  ~:animated 'auto~ uses local content or known poster
capability; use ~:animated t~ for protocol-semantic animated images such as
GIFV backed by MP4.  Disabling autoplay does not change the acquired resource.
~:animation-loop-policy~ accepts ~file~, ~forever~, or ~once~; nil inherits
~video-animation-loop-policy~ at activation.  ~:fit~ controls the live viewport;
one-line center-cropped previews use ~cover~, ordinary previews ~contain~.

When RESOURCE is nil, ~:resolve-function~ receives (SUCCESS FAILURE) on
activation.  SUCCESS accepts a canonical resource alist; FAILURE accepts a
reason string.  Return a cancellation function or nil.  Retirement cancels
pending resolution, and late callbacks cannot resurrect the occurrence.
With ~:animated 'auto~, the resolved local source supplies animation capability;
explicit t or nil survives resolution.  Clients retain authority over protocol
acquisition, account credentials, grants, decryption, and concealed-content
policy; Appkit must not bypass these with a poster URL.

Display the prepared image with the image-string or slice helpers.  Their
source metadata is opaque: clients do not unpack it or attach runtime state.
A Generated Surface mounts prepared media once after a successful render
commit, including header/footer-only and custom renderer output.  Initial
presentation completes after the Surface becomes ready.  Nested
~appkit-with-content-update~ scopes coalesce; failed updates only retire stale
hosts, without mounting partial output.  Completed chatbuf input insertion
also mounts its inserted region.

Leaf printers and reaction/discussion/card helpers only prepare content; they
do not own a second mounting lifecycle.  Outside these completion boundaries,
call ~appkit-media-inline-mount~ after insertion and final property writes:

#+begin_src emacs-lisp
(let* ((image (appkit-media-image-with-resource
               poster original-resource :interaction 'media))
       (start (point)))
  (insert (appkit-media-image-display-string image "[image]"))
  (appkit-media-inline-mount start (point)))
#+end_src

Mounting is idempotent.  Each insertion, including repeated insertion of the
same prepared string, has independent runtime state; all slices of one image
share one host.  Runtime display, keymaps, and ownership live in overlays,
never in the prepared string.  The owner defaults to the exact current
Surface, or the buffer outside a Surface.  Styling preserves a host; replacing
its source plan or text, silent EWOC deletion, mode change, buffer death, or
owner retirement releases its lease.  Initial mounting preserves the normal
live-owner fence.  Clients do not scan for their own emoji hosts.

~appkit-media-inline-host-at-point~ and ~appkit-media-inline-host-live-p~
identify a still-owned occurrence.  ~appkit-media-inline-host-activate~ with
nil follows its interaction policy; ~dedicated~ or ~frame~ promotes the exact
session.  Passive autoplay never opens a viewer or replaces surrounding keys.
Ordinary rich-text copying retains the prepared poster and source plan.
Playback and retirement leave all source text properties unchanged; no
sanitizer, player handle stripping, or restoration pass is needed.  Reinserting
that string creates a new occurrence and never borrows the original player's
state.  The generated-content copy filter still removes presentation metadata
when producing plain copied content.

Completion affixations, header-line strings, and display-only prefixes are not
buffer insertion boundaries and remain posters.  Circular avatars, inset
crops, composite scenes, and navigation covers also remain static unless their
owner deliberately supplies an appropriate playback plan.  A composite or
live/danmaku renderer can keep the lower-level session/Canvas APIs; it must not
replace an entire scene with one item's uncropped source.

~appkit-media-start-video-preview~ extracts only a static JPG.  Playback uses
the original resource, not a generated GIF or bounded preview movie.

Inline Canvas width and height are measured from the inserted image display,
after slice normalization, not from the cached POSTER's unscaled ~Nch~ size.
Rebuild the rows and remount after text scaling so both dimensions follow
the new line height.  Unsliced, pixel-sized posters keep their explicit size.

Cached static Canvas posters remain immutable during slice normalization.
Each resized display copy uses ~video-canvas-copy~ to snapshot the drawn
pixels into an independent backing store.  Copying the Lisp descriptor does
not copy Canvas pixels.  Live playback Canvases retain their original
identity so native frame updates still reach their displayed occurrences.

For a host-owned Canvas, supply its existing display marker or overlay as
~:anchor~, alongside ~:visible-function~, ~:alive-function~, and
~:activate-function~.  The anchor identifies the buffer and occurrence;
video.el resolves its background automatically, without a host color callback.
Standard ~appkit-media-inline-mount~ uses its owned overlay and requires no
additional placement or color arguments.
Use ~video-canvas-create~ for a standalone Canvas.  Resolve its static drawing
background with ~video-background-color~ at the scene's display marker and
pass it to the constructor and ~video-canvas-draw-source~ using ~:background~.
The draw API also accepts ~:fit~.  Local content selects the decoder, including
APNG and Lottie cached without their original extensions.  Canonical resources
retain ~application/lottie+json~ or ~application/zip+dotlottie~ MIME metadata for
routing before acquisition, not for overriding the local decoder.
Use ~appkit-media-resource-poster~ for an immutable, fully drawn first-frame
Canvas without starting playback.
The host redraws its static scene when its colors change; video.el recomposes
live or paused targets without changing their shared player.
The activation callback publishes the Canvas over the complete image span;
copying native frames alone does not replace the host's static display.

Explicit remote opens belong to the initiating Surface's Effects.  Use
~appkit-media-image-acquisition-start~ or ~appkit-media-acquisition-start~ to
acquire a local file; their callbacks only settle the Effect.  A subsequent
committed update starts ~appkit-media-file-presentation-start~.  Shared preview
and avatar acquisition belongs to declarative Resource demands, not rendering
callbacks.

Use ~appkit-media-video-presentation-start~ for managed dedicated playback.
Remote playback starts immediately through video.el and finite media remains
range-seekable; it never waits for a full attachment download.  Under the default
~automatic~ cache policy, Appkit provides an atomic destination under
~appkit-media-video-cache-directory~ and retains the progressive buffer only
when it becomes complete.  Existing complete entries are opened locally.
Use ~:cache-policy 'none~ for streams that must keep buffering session-local.
Already-local files can use ~appkit-media-open-file~ or
~appkit-media-play-video-file~ without remote acquisition orchestration.
Animated content, including extensionless GIFs, uses the native viewer;
ordinary files retain the configured file opener.

Clients provide a stable ~:cache-key~ based on protocol resource identity so
rotating signed URLs address the same complete cache.  A cache is transparent
and may remain incomplete; an explicit download is a separate user action
implemented with ~appkit-media-copy-or-download-resource-async~.

The boundary is strict: video.el owns GStreamer, canonical player state,
temporary sparse buffering, render targets, Canvas transport, waiting UI,
session presentation leases, dedicated buffers, and close-on-last-surface
behavior.  Appkit owns canonical resources, persistent cache policy and
identity, App/Surface lifetimes, and thin resource-aware wrappers around
video.el sessions.  Applications provide resource adaptation and host geometry;
they must pass the active surface or session instead of creating a second
player for a dedicated-reader transition.

Finite local audio playback uses ~appkit-media-player-start-file~.  One
~appkit-media-player-session~ owns its process, progress timer, pause/resume
position, and optional Appkit owner handle.  Its lifecycle follows Telega's
ffplay model: parse player progress, pause by terminating the current process,
and resume with a fresh process at the retained timestamp.  MPV sessions
override inherited ~idle~ and ~keep-open~ settings so terminal cleanup remains
authoritative.  Clients provide local-file acquisition, duration metadata,
resource invalidation callbacks, and protocol identity; they do not own player
processes or sentinels.

** Composer attachment acquisition

Reserve Telega's attachment meanings: ~C-c C-a~ chooses an extensible staging
action, ~C-c C-f~ selects local media/files, and ~C-c C-v~ acquires clipboard
files or image bytes.  None submits a message.  A universal prefix forces a
document only when the provider has a distinct document kind; it must not
silently become spoiler, visibility, or preview.

Use ~appkit-media-read-file-name~ for readable regular files and
~appkit-media-clipboard-source~ for acquisition without upload or staging.
The latter returns ~(:files PATHS)~ or
~(:mime-type MIME :suffix SUFFIX :data BYTES)~.  Local file URIs take precedence
over PNG/JPEG/BMP bytes; invalid or nonlocal URI entries reject the entire list.
Native selection and available Wayland, macOS, or X11 tools share this contract.
The client owns any private staging file and retains it through captured sends;
ordinary clipboard files remain user-owned.

Clients without attachment upload leave these keys unbound.  Zulip uses
~C-c C-p~ for preview and ~C-c C-o~ for message operations; Discourse uses
~C-c #~ for topic tags and ~C-c C-p~ for preview.


** Completion

Appkit owns token bounds, candidate metadata, CAPF and picker
presentation, atomic commit, and ordered TAB dispatch.  Clients own
member and server-emoji lookup, avatar acquisition, protocol objects,
and insertion callbacks.  A selected mention remains a client-defined
structured composer object.

Bounded image catalogs use ~appkit-chat-completion-read-visual~.  It
keeps the label and hidden search aliases in the native alist completion
title, supplies each preview through the native ~affixation-function~,
and maps the selected title back to the opaque candidate.  Prefixes may
be strings or functions of the candidate; function prefixes let clients
consult their own image cache only when the completion UI requests an
affix.  Clients remain responsible for resource acquisition and cache
invalidation.  Frontends may strip candidate text properties without
discarding the independently affixed preview.

For asynchronously loaded catalogs, pass ~:subscribe~ and an initially empty
candidate list.  The reader enters the minibuffer before calling the subscription
with a ~publish~ function.  Call ~publish~ with replacement candidates and an
optional nonselectable status; publishing the same list refreshes lazy previews.
The subscription returns an optional cleanup function.  Exit, error, and quit
detach it and fence late publications from later minibuffer sessions.
The reader owns native completion-table and frontend refresh state; the client
owns data acquisition and resource notifications.  Do not hold a Surface render
pass open for the lifetime of an interactive picker.

Keep dynamic or large nonvisual catalogs on
~appkit-chat-completion-read~.  Candidate ~group~ metadata becomes the
native completion ~group-function~, so capable frontends render sections
without a Consult dependency.

On Emacs versions that provide the built-in emoji database,
~appkit-chat-emoji-*~ adds shared ~:unicode_name:~ candidates grouped by
the database's top-level Unicode categories.

* Runtime update model

An application defines one immutable ~appkit-app-type~.  Its ~init~ and
~update~ callbacks return ~appkit-next~ values: the next canonical model, an
explicit render disposition, and a bounded list of closed commands.  Appkit
serializes each accepted transition, advances the revision, folds commands,
then commits post messages and starts finite keyed Effects.  Callbacks never
receive the mutable loop or registry.

A generated buffer defines one ~appkit-surface-type~ and one
~appkit-generated-renderer~.  The Surface owns its local model; its parent App
is exposed only as a pass-scoped read view.  Rendering runs after the final
model commit for the pass, in the exact host buffer.  A renderer may merge
requests and recover once, but may not mutate the domain model, post messages,
or start work.

Recovery must discard invalid presentation caches and reconstruct from committed
state.  Reissuing a full render request against the same damaged cache is not
recovery.  Without an explicit recovery implementation, the render error faults
the Surface.

Use ~appkit-app-send~ / ~appkit-surface-send~ for a synchronous external
transition and ~appkit-app-post~ / ~appkit-surface-post~ for asynchronous
external admission.  Neither public post path is legal while any Appkit loop
is draining.  An ~init~, ~update~, renderer, Effect starter, or mapper that
needs later work must return an ~appkit-command-post-message~ or
~appkit-command-start-effect~ through ~appkit-next~ instead.  Expected domain
rejection returns ~appkit-next-reject~; ~appkit-loop-reject~ is an internal
state-machine result, not a client API.

An Effect starter receives owned input and observe/resolve/reject gates.
Synchronous gate calls only stage payload; their mappers run in later passes.
Replacing an equal Effect key revokes callback authority before physical
cancellation.  Each Effect runtime coalesces ready instances behind one
control wake, so synchronous completion cannot consume one control slot per
active Effect.

An App or Surface type may provide a pure ~sources(model)~ callback returning a
bounded desired set of ~appkit-source-spec~ values.  Source keys are unique;
an unchanged key and identity retains the current long-lived producer, while
an identity change revokes it before admitting a successor.  Terminal
instances remain tombstones until their identity changes or the key is absent
from one desired set.  Use ~lossless~, ~latest~, or ~coalesce-by-key~ emission
policy with the required positive pending bound.  Event and close callbacks
only enter the runtime gate; their mappers execute in later passes.

Bidirectional Sources expose transport sends only through
~appkit-command-source-intent~.  The command names the expected Source identity,
owned payload, and a function-symbol result mapper.  Outcomes are
~accepted~, ~backpressured~, ~closed~, or ~stale~ and always map in a later
pass.  A ~quiescent-transport~ Source delays replacement until its concrete
cancellation capability reports physical quiescence.

Projection rows may return ~appkit-resource-demand~ values bounded by the App
coordinator's entry capacity, not an independent per-render limit.
Include each demand's key in the row's ~dependencies~ as well as supplying
~resource-demands~: acquisition interests do not populate the redraw index.
The standard projection renderer commits interests only after successful buffer
mutation.  Resource completion passes through the App coordinator and exact
Surface incarnation, then redraws only retained dependency rows without calling
the projector or advancing a domain revision.  Each owner coalesces completion
work behind one control wake; synchronous cache hits do not consume one control
slot per Resource.  Acquisition still obeys the broker's active and queued bounds.

The host buffer is persistent ownership; windows are temporary viewports.
Major mode setup precedes attachment.  Killing the exact buffer or changing
its major mode synchronously stops the Surface.  Renaming, burying, hiding all
windows, or killing an indirect clone does not.  Generated structural edits
are undo-free; editable document state remains governed by the compose/editor
module that owns it.

Width-sensitive Generated Surfaces should call
~appkit-surface-enable-responsive-geometry~ with a callback that posts their
bounded geometry render request, then call
~appkit-surface-refresh-responsive-geometry~ after the host is displayed.
Renderers read the measured canonical-window width through
~appkit-surface-responsive-width~.  Window and line-number changes notify only
when the measurement changes; a no-argument text-scale hook always notifies so
clients can retire pixel caches and rebuild images for the new face metrics.

Topic publish, terminal reset, existing-Surface policies, and editable/hybrid
Surface control are later protocol layers.  Do not reproduce them with direct
callbacks or restore the removed App/View control plane.

* Source-preserving display markers

Generated readers may keep protocol source markers in the buffer while replacing
them visually.  Use ~appkit-ui-apply-source-line-prefix~ with one presentation
character for every literal source character.  The one-to-one projection keeps
real visual columns for cursor motion while the original prefix remains
copyable; soft wraps receive the supplied continuation prefix without changing
an outer ~line-prefix~.  ~appkit-discussion-mode~ installs
~appkit-ui-buffer-substring-filter~ for the whole generated reader;
~appkit-chatbuf-mode~ limits cleanup to generated content before its input.
Standalone generated readers install the filter as their buffer-local
~filter-buffer-substring-function~.  Copied text keeps source characters while
dropping ~display~, ~line-prefix~, and ~wrap-prefix~ presentation properties.
The filter's optional ~PRESENTATION-END~ boundary supports mixed generated and
editable selections.  ~appkit-ui-vbar-string~ supplies a GUI/terminal vertical
marker; ~appkit-ui-tinted-background-face~ derives a subtle background from an
existing accent face without changing the text foreground.

Cards have no implicit outer indentation: ~appkit-ui-card-prefix-state~ adds
only the border by default.  Bind ~appkit-ui-card-indent-prefix-state~ (or
~appkit-ui-card-indent-prefix~) when a chat card must reuse an existing body
gutter; its border replaces the gutter's last column.  A discussion renderer
that applies its body prefix after insertion should leave the card indent
empty, so the parent prefix is applied only once.

* Task queues

The shared task queue deduplicates equal keys across active and
waiting work, starts tasks in FIFO order up to a live adjustable
limit, and guards every completion with a one-shot token.  A starter
may return an ~appkit-handle~ or a zero-argument cancellation
function.  Killing the owning app or view closes the queue and makes
stale completions inert.

~appkit-task-queue-cancel-keys~ retires all matching work before it
frees a slot.  Synchronous completion is delivered only after the
starter returns its handle.

* Semantic keys and Evil adapters

Declare capabilities once in the native map.  ~appkit-bindings-define~ follows
evil-collection's action/command approach without requiring Evil:

#+begin_src emacs-lisp
(appkit-bindings-define 'example-mode-map 'read-only
  'activate #'example-open
  'app-menu #'example-transient
  'refresh #'example-refresh
  'quit #'quit-window)
#+end_src

The context is ~read-only~ or ~input~.  Declare only implemented capabilities;
command and prefix-map definitions are accepted.  The shared theme provides
native bindings immediately.  The adapter's optional Evil setup calls
~appkit-bindings-enable-evil~ on the same map; declaration, map, and Evil may
arrive in any order.  Keep protocol-specific controls in their existing maps,
using ~appkit-evil-map~ when they need modal bindings.

| Action | Native | Evil |
|--------+--------+------|
| Application menu | ~C-c t~ | ~ga~, ~C-c t~ |
| Help | ~C-c ?~, ~?~ in read-only views | ~g?~ |
| Navigation | ~M-g~ | ~gA~ |
| Refresh (Appkit extension) | ~g~ in views, ~C-c g~ in input | ~gr~ |
| Edit message / committed compose item | ~e~ on the timeline | ~i~ |
| Delete message / committed compose item | ~d~ on the timeline | ~D~, ~dd~ |
| Return / force newline | ~RET~, ~<return>~ / ~S-RET~, ~S-<return>~ | same |
| Explicit submit, when supported | ~C-c C-c~ | same |
| Input options | ~C-c C-o~ | same |
| Preview / cancel | ~M-RET~, ~M-<return>~ / ~C-c C-k~ | same |
| Attachment chooser / file / clipboard | ~C-c C-a~ / ~C-c C-f~ / ~C-c C-v~ | ~Za~ / ~Zf~ / ~Zv~ |
| Code-block editor, when supported | ~C-c '~ | same |

~i~ edits the actual message or committed compose item at point; it is not an
input-focus shortcut.  ~C-c '~ follows ~telega-mnz-chatbuf-attach-code~:
open a real source editor and stage its result, never send or merely focus
input.  Slackit provides this capability.  Clients without a corresponding
operation leave the key unclaimed.

The message-edit/delete and attachment modal keys follow evil-collection's
Telega adapter; navigation, input options, preview and cancellation follow
Telega's native map.  ~C-c t~ follows the local Telega application prefix.
Refresh, pagination and generic mark roles are Appkit extensions, not claims
about Telega's message keys.  In particular, Telega's chat ~C-c C-c~ cancels a
filter; Appkit's optional submit role preserves clients' explicit publishing
or editor-commit convention.  No extra ~C-c RET~ or dedicated ~C-j~ binding
is installed; inherited Emacs ~C-j~ remains available.

Return is an application policy, not a universal send operation.  Chat clients
may submit; public posts, mail, and forum composers retain their editing
policy.  Completion-in-region gets Return first.  Use
~appkit-chatbuf-dispatch-return~ for shared input/timeline geometry: exact
inline action, native button, client timeline action, then input focus.
Input and timeline command remappings are honored.  Bind both Return event
forms; native Wayland can deliver ~<return>~ instead of character ~RET~.

Keep message capabilities on point-sensitive timeline maps.  They must not
remain active in editable input.  The read-only native projection steps aside
in modal states, preserving Evil's bare ~?~ search and visual ~o~ motion.
Use ~appkit-evil-set-initial-states~ and ~appkit-evil-normalize-buffers~ for
client lifecycle setup.  ~appkit-evil-define-readonly-keys~ supplies baseline
quit/help capabilities for auxiliary views.

~appkit-binding-overrides~ replaces individual theme properties, including
explicit nil; ~:enabled nil~ disables a role.  ~appkit-bindings-refresh~
updates registered adapters while preserving user replacements.  It removes
retired local entries rather than shadowing inherited keys with nil.

Snipe eligibility is centralized.  Appkit registers
~appkit-bindings-buffer-p~ once in ~evil-snipe-disabled-functions~; native map
identity and parent inheritance cover views and editable composers.  Do not
add per-client Snipe disable hooks.  ~evil-snipe-refresh~ reconciles automatic
activation after a late policy load.  Explicit local Snipe commands remain
available and are not overwritten by that refresh.

** Matrix attachments and replies

The room composer keeps attachment objects in the property-preserving Appkit
input.  ~C-c C-f~ chooses a local file, ~C-c C-v~ stages clipboard files or image
bytes, and ~C-c C-a~ opens the attachment chooser.  ~C-c C-d~ detaches an
attachment.  A universal prefix forces a generic file instead of inferred media.
Return or ~C-c C-c~ submits the captured text/caption and ordered attachments.

~message.send~ requires ~room_id~, ~subscription_id~, ~body~, an ~attachments~
array, and optional ~reply_to~.  Each attachment carries an absolute local path,
filename, MIME type, and optional image dimensions.  The backend prevalidates
sources and delegates queue persistence, media upload, encryption and retry
policy to the SDK.  Multiple attachments become separate events; only the first
receives the draft caption, and all retain the captured reply target.

Queue admission reports ~accepted~ and ~total~, not delivery confirmation.
Full acceptance clears only the exact captured draft.  Partial acceptance removes
only the accepted prefix and consumed caption; unaccepted attachments remain.
Newer drafts are retained and require submission review rather than automatic
resubmission.  Private clipboard files are App-owned, with separate draft and
captured-send references; closing a view cannot revoke an admitted send's source.
Selected user files are never deleted.

Room operation feedback is emitted through post-commit echo-area Effects and
~*Messages*~, never stored as composer content.  Send, edit, redaction and
submission-review feedback cannot add persistent rows above the input.

Incoming quotes show the SDK relationship, original author and preview, with
explicit loading, unavailable and error states.  Missing preview details are
fetched through the SDK without blocking timeline updates; fallback body/HTML
is not treated as a relation.  Return or click follows the exact loaded original.
An original outside the loaded timeline offers its Matrix permalink and
load-older guidance, not a jump to a nearby message.

Reply authors use the same stable name color as message headings.  Composer
reply context uses the shared two-line ~appkit-chatbuf-aux-render~ card: a
~Reply to AUTHOR~ title, author-colored accent, and a bounded content preview.

Timeline ~r~ stages the exact SDK-replyable server event in composer aux state
without replacing the ordinary draft.  ~C-c C-k~ cancels an idle reply while
retaining text and attachments.  Session, subscription, event identity and SDK
reply capability are revalidated before admission.

** Matrix message mutations

Matrix timeline ~e~ / Evil ~i~ loads the exact own server event into the input
and retains the preceding rich draft and reply state.  Return queues ~message.edit~,
not ~message.send~.  Acceptance restores the preceding draft only if the
captured edit revision still owns the input; failures and newer edits remain.
~C-c C-k~ cancels an idle edit and restores its saved draft.

Timeline ~d~ / Evil ~D~ or ~dd~ confirms ~message.redact~.  The captured Surface,
session, subscription, event identity and SDK permission are checked again
after confirmation.  There is no local deletion substitute: SDK timeline
updates supply the stable tombstone.  Local queue entries and unavailable,
undecrypted or unauthorized events do not acquire edit capabilities.

The backend requires ~room_id~, ~subscription_id~ and ~event_id~ for mutations
(plus ~body~ for edits), revalidates current room permissions, and delegates
encryption and queue ownership to the SDK.  Text/notice/emote subtype, reply
identity, mentions and encrypted media sources survive supported body/caption
edits.  An uncertain edit uses the existing submission-review gate rather
than automatically retrying.

** Matrix message images

Genuine SDK ~m.image~ events retain their caption and render local originals
through ~appkit-media-resource-poster~ / ~video-source-poster~.  Preview budgets
are default-scale pixels: line counts follow text zoom, preserve aspect ratio,
and shrink only to fit the current window.  Canvas posters are drawn from the
original at the actual display size; animated playback uses the same geometry.
Return or click opens a still-image viewer or toggles animation, never submits
the composer.  Non-Canvas displays retain captions and filenames without fetching.

~media.image~ requires ~room_id~, ~subscription_id~, ~event_id~ and ~source_id~.
The opaque source identity covers the complete SDK media source, including
encrypted attachment metadata.  The SDK owns authenticated download, decryption
and hash verification; URLs and attachment keys do not cross the frontend wire.
Account-private Resources share one interest replacement with avatars and fence
late completions against source replacement, redaction and subscription teardown.
Private immutable originals live under ~STORE/media/GENERATION/~; the 32 MiB
admission limit is checked after SDK buffering, not a streaming memory limit.

* Development

Run from the monorepo root with source directories from the existing package
registry.  ~dev-with-source-loads~ prevents stale project bytecode from hiding
source changes; no package-manager cache is used.  Initialize dependencies
before the ERT interaction guard:

#+begin_src sh
systemd-run --user --wait --pipe \
  -p "WorkingDirectory=$PWD" -p MemoryMax=768M -p MemorySwapMax=0 \
  -p RuntimeMaxSec=120s -p TasksMax=32 \
  emacs -Q --batch -L emacs-dev -l dev --eval '
(let* ((repository (expand-file-name "."))
       (directories
        (cl-loop for (_ . entry) in dev-jjosh-package-registry
                 append
                 (let ((root (expand-file-name (plist-get entry :path)
                                               repository)))
                   (mapcar (lambda (path) (expand-file-name path root))
                           (plist-get entry :load-paths))))))
  (dev-with-source-loads directories
    (require (quote appkit))
    (add-to-list (quote load-path)
                 (expand-file-name "appkit-apps/appkit.el/test" repository))
    (require (quote org))
    (require (quote notifications))
    (let ((result
           (dev-run-test-files
            (directory-files "appkit-apps/appkit.el/test" t "-test\\.el$"))))
      (prin1 result)
      (kill-emacs (if (zerop (plist-get result :unexpected)) 0 1)))))'
#+end_src

Replace the test-file list for a client package and preload that client before
the guard.  Use a separate graphical Emacs for Canvas geometry, actual native
playback, and input interaction; skipped batch tests are not graphical proof.
Never run account-resetting client suites in a logged-in daily session.
